== Arrays

Laut Java-Dokumentation ist ein Array ein *Objekt, das eine feste Anzahl von Werten desselben Typs* enthält. Die Elemente eines Arrays sind indiziert, was bedeutet, dass mit Zahlen (sogenannten *Indizes*) auf sie zugegriffen werden kann.

Ein Array kann als eine nummerierte Liste von Zellen betrachtet werden, wobei jede Zelle eine Variable ist, die einen Wert enthält. In Java beginnt die Nummerierung bei (_Index_) `0`. Ein Array erkennt man an den *eckigen* Klammern `[]`.

[,java, subs=normal]
----
                       *Index*: {  0 ,  1 ,  2  , ... }
                                 :    :    :
String[] array = new String[] { "A", "B", "C" , ... };
----

Es gibt Arrays vom primitiven Typ und Arrays von komplexen Objekttypen. Das bedeutet, dass Arrays vom Typ `int`, `float`, `boolean` usw. verwendet werden können, aber auch Arrays vom Typ `String`, `Object` und benutzerdefinierte Typen.

Ein paar *Beispiele*:

[,java]
----
int[] arr1 = new int[4];             // feste Länge
int[] arr2 = new int[] {1, 2, 3, 4}; // mit initialen Werten
int[] arr3 = {1,2,3,4};              // ohne 'new'

String[] arr4 = new String[3];
String[] arr5 = new String[]{};
String[] arr6 = {"A", "xdre", "Frg%5"};
----

=== Java Collections API

Die Java-Collection-Interfaces bilden die Grundlage des Java Collections Frameworks. Alle zentralen Collection-Interfaces sind generisch.
Zum Beispiel `public interface Collection<E>`. Die Syntax `<E>` steht für Generics (_mehr dazu später im Kapitel_ `Generics`).

. *Collection-Interface*
Dies ist die Wurzel der Collection-Hierarchie. Eine Collection repräsentiert eine Gruppe von Objekten, die als ihre Elemente bezeichnet werden. Einige grundlegende Operationen werden bereitgestellt.

. *Iterator-Interface*
Das Iterator-Interface stellt Methoden bereit, um über die Elemente einer Collection zu iterieren. Iteratoren ermöglichen es dem Aufrufer, während der Iteration Elemente aus der zugrunde liegenden Collection zu entfernen.

. *Set-Interface*
Ein Set ist eine Collection, die keine Duplikate, doppelte Elemente, enthalten darf.
Die Java-Plattform enthält drei allgemeine Set-Implementierungen: `HashSet`, `TreeSet` und `LinkedHashSet`.

. *List-Interface*
Eine List ist eine geordnete Collection und kann doppelte Elemente enthalten. Auf jedes Element kann über seinen Index zugegriffen werden.
Listen haben eine dynamische Länge. `ArrayList` und `LinkedList` sind Implementierungsklassen des List-Interfaces.

. *Queue-Interface*
Eine Queue ist eine Collection, die mehrere Elemente vor deren Verarbeitung hält.
Neben den grundlegenden Collection-Operationen bietet eine Queue zusätzliche Einfüge-, Entnahme- und Überprüfungsoperationen.
Queues ordnen Elemente typischerweise (aber nicht zwingend) nach dem FIFO-Prinzip („first-in-first-out“).

. *Dequeue-Interface*
Eine lineare Collection, die das Einfügen und Entfernen von Elementen an beiden Enden unterstützt. Der Name *deque* ist die Kurzform von *„double-ended queue“*.

. *Map-Interface*
Eine Java-Map ist ein Objekt, das Schlüssel zu Werten zuordnet. Eine Map darf keine doppelten Schlüssel enthalten; jeder Schlüssel kann höchstens einem Wert zugeordnet sein.
Die Java-Plattform enthält drei allgemeine Map-Implementierungen: `HashMap`, `TreeMap` und `LinkedHashMap`.

. *SortedSet-Interface*
Ein SortedSet ist ein Set, das seine Elemente in aufsteigender Reihenfolge hält. SortedSets werden für natürlich geordnete Mengen verwendet.

. *SortedMap-Interface*
Eine Map, die ihre Zuordnungen in aufsteigender Schlüsselreihenfolge verwaltet. Dies ist das Map-Äquivalent zu SortedSet.
SortedMaps werden für natürlich-geordnete Sammlungen von Schlüssel/Wert-Paaren verwendet.

TIP: Übrigens, das ist eine beliebte Prüfungsfrage: _„Welche Eigenschaften hat das Collections-Interface ...?“_

=== Synchronized Wrappers

Die *synchronisierten* Wrapper fügen einer beliebigen Collection eine automatische Synchronisierung (Thread-Sicherheit) hinzu.
Jedes der sechs zentralen Collection-Interfaces – Collection, Set, List, Map, SortedSet und SortedMap – besitzt eine statische Fabrikmethode, die eine synchronisierte (thread-sichere) Collection zurückgibt, die auf der angegebenen Collection basiert.


=== Unmodifiable Wrappers

*Unmodifiable* Wrapper entziehen einer Collection die Möglichkeit, verändert zu werden. Sie fangen alle Operationen ab, die die Collection modifizieren würden, und werfen stattdessen eine `UnsupportedOperationException`.

Die Hauptanwendungsfälle sind:

- Um eine Collection unveränderlich zu machen, sobald sie aufgebaut ist
- Um bestimmten Clients nur Lesezugriff auf Datenstrukturen zu geben (eine Referenz auf die ursprüngliche Collection behalten, aber eine Referenz auf den Wrapper ausgeben)
- Um `ConcurrentModificationException` zu vermeiden
